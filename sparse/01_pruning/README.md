# 模块一：结构化剪枝 / 非结构化剪枝

> 目标：理解"移除冗余权重或神经元"的各种粒度，掌握 Magnitude Pruning → Wanda → SparseGPT → LLM-Pruner 的演进逻辑，并能说清每种方法**省的是带宽还是算力**。

---

## 1. 剪枝在解决什么问题

一个 70B 的模型，FP16 权重约 140GB，推理时每生成一个 token 都要把权重从 HBM 搬到计算单元。剪枝把一部分权重置零，理想情况下：

- **省显存 / 省带宽**：零权重可以不存、不搬（需要稀疏存储格式）。
- **省算力**：零权重参与的乘加可以跳过（需要硬件/算子支持）。

⚠️ **最关键的一点**：这两件事不是一回事。**非结构化剪枝通常只省带宽，不省算力**——因为稠密 GEMM 单元不知道哪里有零，照样算。只有结构化/N:M 这种"规则"的稀疏，硬件才能真正跳过。

---

## 2. 三种剪枝粒度（贯穿全局的分类）

| 粒度 | 做法 | 稀疏率上限 | 精度 | 硬件加速 | 典型 |
|------|------|-----------|------|---------|------|
| **非结构化（unstructured）** | 任意位置单个权重置零 | 高（50–90%） | 最好 | ❌ 需专用稀疏库，通用 GEMM 不加速 | Magnitude、Wanda、SparseGPT |
| **结构化（structured）** | 整行/整列/整个注意力头/整层移除 | 较低（20–50%） | 较差 | ✅ 直接变小矩阵，通用 GEMM 立刻变快 | LLM-Pruner |
| **半结构化 N:M** | 每连续 M 个元素中保留 N 个 | 固定（2:4 = 50%） | 较好 | ✅ Ampere+ Tensor Core 原生支持 | 见模块四 |

一句话记忆：**越不规则 → 精度越好但越难加速；越规则 → 越好加速但精度损失越大。** 这就是剪枝的核心权衡。

---

## 3. 方法一：Magnitude Pruning（幅度剪枝）

### 原理
最朴素的假设：**权重的绝对值 = 重要性**。

$$\text{score}_{ij} = |W_{ij}|, \qquad M_{ij} = \mathbb{1}[|W_{ij}| \ge \tau]$$

其中 $\tau$ 是使整体稀疏率达到目标 $s$ 的阈值：$\tau = \text{k-th smallest}(|W|,\; k = \lceil(1-s)\cdot n\rceil)$。

### 两个变体
- **Layerwise（逐层）**：每个权重矩阵独立剪到相同稀疏率。
- **Global（全局）**：所有权重放一起排序取统一阈值 → 不同层稀疏率不同，通常精度更好。

> 一般**优先用 global**，因为它允许"重要层少剪、冗余层多剪"。

### 局限
完全不看输入数据。一个权重虽然小，但如果它对应的输入激活一直很大，它对输出的贡献 `W·X` 并不小 → 这就是 Wanda 的动机。

→ 见 `01_magnitude_pruning.py`

## 4. 方法二：Wanda（激活感知剪枝）

### 原理
重要性应该同时看权重和它"看到"的激活：

$$\text{score}_{ij} = |W_{ij}| \cdot \|\mathbf{X}_j\|_2$$

其中 $\mathbf{X}_j$ 是第 $j$ 个输入通道在校准集上的激活，$\|\mathbf{X}_j\|_2 = \sqrt{\sum_{n} X_{n,j}^2}$。

### 关键细节
1. **只需少量校准数据**（如 128 条样本跑一次前向），无需训练、无需梯度。
2. **比较范围是每个输出神经元内部**（即 $W$ 的每一行内比较输入维度），而不是全局比较——这保持了每个输出神经元被剪掉的比例一致。
3. 计算成本：一次前向 + 一次矩阵乘，秒级完成。

### 为什么有效
$\|\mathbf{X}_j\|_2$ 大的输入通道，其对应权重即使小也"影响面广"。Wanda 用极低成本引入了数据分布信息，效果远超纯 magnitude，接近需要二阶信息的 SparseGPT。

→ 见 `02_wanda.py`

## 5. 方法三：SparseGPT（二阶信息 + 误差补偿）

### 原理
SparseGPT 把剪枝看成一个**重构问题**：找稀疏权重 $\hat{W}$，使得在给定输入 $\mathbf{X}$ 下输出尽量不变：

$$\min_{\hat{W}} \|W\mathbf{X} - \hat{W}\mathbf{X}\|_2^2 \quad \text{s.t.} \quad \hat{W} \in \text{sparsity pattern}$$

这等价于经典的 **Optimal Brain Surgeon (OBS)** 问题，用二阶泰勒展开，Hessian 为：

$$\mathbf{H} = 2\mathbf{X}^\top\mathbf{X} \quad (\text{样本均值归一化})$$

### 算法三步
1. **算 Hessian 逆**：$\mathbf{H}^{-1}$（加阻尼 $\lambda = 0.01\cdot\text{mean}(\text{diag}(\mathbf{H}))$ 保证可逆）。
   注意 $\mathbf{H}$ 只在**输入维度**上，与输出行数无关，所以可以逐层独立算。
2. **显著性打分选 mask**：$\text{score}_{ij} = \dfrac{W_{ij}^2}{[\mathbf{H}^{-1}]_{jj}^2}$，剪掉分数最低的。
   分母的含义：该权重位置对重构误差的"敏感度"——$\mathbf{H}^{-1}$ 对角元大的列，剪掉后能被其他权重补偿得更好，所以更该剪。
3. **OBS 误差补偿**（SparseGPT 的灵魂）：每剪掉一块权重，把它的影响按 $\mathbf{H}^{-1}$ 分摊到**未剪掉的权重**上：

$$\delta = -\frac{W_{\cdot,p}}{[\mathbf{H}^{-1}]_{pp}} \cdot \mathbf{H}^{-1}_{p,\cdot}, \qquad W_{\text{remain}} \mathrel{+}= \delta$$

### 为什么要分块（block）
对整层一次性求 $\mathbf{H}^{-1}$ 是可行的，但官方实现按列分块（blocksize=128）处理，并且**把当前块的误差继续传播到后续列**：

$$W_{[:, i_2:]} \mathrel{-}= \text{Err}_1 \cdot \mathbf{H}^{-1}_{[i_1:i_2,\; i_2:]}$$

这样逐块累积补偿，精度更高。

### 与 Wanda 的对比
| | Wanda | SparseGPT |
|---|---|---|
| 是否需要二阶信息 | 否（一阶激活范数） | 是（Hessian 逆） |
| 是否有误差补偿 | 否 | 是（OBS） |
| 速度 | 更快 | 稍慢（要矩阵求逆） |
| 高稀疏率（>70%） | 退化 | 明显更好 |

→ 见 `03_sparsegpt.py`

## 6. 方法四：LLM-Pruner（结构化剪枝）

### 原理
前面三种都是非结构化（单个权重置零），无法直接加速。LLM-Pruner 移除**整个结构单元**：

- **神经元**：MLP 中间层的某个神经元（对应 `fc1` 的一行 + `fc2` 的一列）
- **注意力头**：整个 head（对应 `q/k/v_proj` 的对应行 + `o_proj` 的对应列）
- **层**：整个 Transformer block

### 关键技术点
1. **耦合结构（coupled structure）**：剪一个神经元不是删一个权重，而是**同时删掉与之关联的一整组权重**（fc1 的行、fc2 的列）。必须保证维度仍然对得上。
2. **重要性评估**：通常用该结构的权重范数，或基于激活的统计量。
3. **剪后必须恢复**：结构化剪枝破坏大，**必须微调**。实践中常用 **LoRA 微调**或**蒸馏**（用原模型当 teacher）在少量数据上恢复——这也是 JD 中"蒸馏"与"稀疏化"结合的典型场景。
4. **依赖感知**：残差连接、LayerNorm、embedding 与 lm_head 的耦合关系都要处理，否则维度对不上。

### 结构化剪枝的真正价值
**它是唯一能让模型在通用硬件上立刻变快的方法**。因为矩阵真的变小了：
- 剪掉 50% 的 MLP 神经元 → `fc1` 从 `[d_ff, d]` 变成 `[d_ff/2, d]` → FLOPs 直接减半。

对比非结构化剪枝：稀疏率 50% 但矩阵尺寸不变，通用 GEMM **一点都不快**。

→ 见 `04_structured_pruning.py`

## 7. 四种方法横向对比

| 方法 | 粒度 | 需要数据 | 需二阶信息 | 误差补偿 | 剪后恢复 | 直接加速 |
|------|------|---------|-----------|---------|---------|---------|
| Magnitude | 非结构化 | 否 | 否 | 否 | 可选 | ❌ |
| Wanda | 非结构化 | 少量校准 | 否 | 否 | 可选 | ❌ |
| SparseGPT | 非结构化 | 少量校准 | 是（Hessian） | 是（OBS） | 可选 | ❌ |
| LLM-Pruner | 结构化 | 少量校准 | 否 | 否 | **必须**（微调/蒸馏） | ✅ |

> 注：三种非结构化方法若要真正加速，需配合模块四的 **N:M 结构化稀疏**或稀疏 GEMM 库（cuSPARSE / CUTLASS sparse）。

## 8. 剪枝后的恢复手段（重要）

剪枝必然掉点，工业界的标准做法是"剪枝 + 恢复"组合拳：

| 手段 | 做法 | 成本 |
|------|------|------|
| **LoRA 微调** | 冻住剪枝后权重，只训练低秩适配器 | 低 |
| **蒸馏** | 用原稠密模型当 teacher，剪枝模型当 student，对齐 logits | 中 |
| **全参微调** | 直接训剪枝后模型 | 高 |

其中**蒸馏**最常用：因为 teacher 就是剪枝前的自己，不需要额外大模型，且 logits 对齐信号比单纯 CE 更丰富。

---

## 9. 实践建议

- **目标稀疏率**：非结构化 50% 通常几乎无损；70% 开始明显掉点；>90% 需要配合恢复训练。
- **哪些层敏感**：第一层（embedding 后）和最后一层（lm_head 前）通常更敏感，建议少剪。
- **校准集**：128–256 条、分布要接近真实输入（随机 token 会导致剪错）。
- **先剪后量 or 先量后剪**：一般**先剪枝再量化**（量化会改变权重分布，先剪更干净），也可以联合优化。

## 10. 与 vLLM / SGLang 的对应

| 概念 | 源码位置 |
|------|---------|
| 稀疏/压缩的线性层 | `vllm/model_executor/layers/linear.py`（各类 LinearMethodBase 实现） |
| Marlin / Machete 等压缩 GEMM kernel | `csrc/quantization/`、`vllm/model_executor/layers/quantization/` |
| 剪枝模型加载 | vLLM 本身不做剪枝（训练侧工具如 SparseGPT/LLM-Pruner 产出权重），但需支持对应 checkpoint 格式 |
| 结构化剪枝后的小模型 | 直接走标准 `nn.Linear`，无需特殊 kernel |

**工程要点**：vLLM 里真正落地的"稀疏"主要是 **N:M 结构化稀疏 + 量化**（见模块四），因为只有它们能被 Marlin/CUTLASS kernel 真正加速。纯非结构化剪枝在 vLLM 里基本没有加速收益。

## 11. 面试高频问题

1. **非结构化剪枝 50%，推理能快一倍吗？** 不能。矩阵尺寸没变，稠密 GEMM 不认识零。只有省存储和（专用稀疏库下）省带宽。
2. **Wanda 和 Magnitude 的区别？** Wanda 用激活范数加权，考虑了输入分布。
3. **SparseGPT 为什么能一次（one-shot）剪完不掉点？** 因为它用 Hessian 二阶信息 + OBS 误差补偿，把剪掉权重的影响分摊到剩余权重上。
4. **结构化 vs 非结构化怎么选？** 要通用硬件立刻加速 → 结构化；要极限压缩率且只省带宽 → 非结构化；要两者兼顾 → N:M（模块四）。
5. **剪枝后精度掉了怎么办？** 蒸馏/LoRA 微调恢复。
